# Kickoff prompts

## First task

Paste into a fresh worker with access to this repository:

```text
Work in techrote/MachineHumanAudioCybersemiotics on #1 / MHAC-R001.
Reconcile live main, the complete issue and comments, branches/PRs and CI.
Read AGENTS.md, RAG.md, docs/PROGRAMME.md, docs/AGENT_RUNBOOK.md and all
issue-specific authorities. Implement the research registries, validators
and reproducible CI within the issue's scope. Do not begin the literature
review or write research findings. Use high reasoning effort; disjoint
subagent work and read-only critique are permitted. Complete tests,
documentation, PR, review fixes, successful final-head checks, squash merge
and post-merge verification. Never bypass checks/approvals or fabricate
research evidence. Record true blockers and an exact checkpoint. Report
merge/check evidence and whether #2 is dependency-ready.
```

## Continue the programme

Use only when the user has authorized a multi-issue run:

```text
Continue the research programme in techrote/MachineHumanAudioCybersemiotics.
Read AGENTS.md, RAG.md, docs/PROGRAMME.md and docs/AGENT_RUNBOOK.md; reconcile
live issues, acceptance artifacts, main, branches, PRs and CI. Resume active
unblocked work before starting a new dependency-ready issue. Read every
selected issue and its full referenced authorities. Work one mutable repo
only; use disjoint lanes/subagents where safe and serialize integration.
Complete each issue through tests, PR, review fixes, final-head checks,
squash merge and post-merge verification before marking it complete.
Do not bypass approvals, reinterpret missing evidence as completion, or
start human-gated actions without actual authorization. Continue unblocked
research scope; checkpoint genuine gates. Stop after the authorized scope
or the internal #18 package, with #19/#20 still gated unless separately
authorized. Report landed work, evidence, remaining limits and the next
ready work. Do not merely produce another plan.
```

## Resume rule

A previous status summary is a pointer, not authority. Re-fetch the target issue and actual artifacts. Do not repeat already completed work or adopt a stale checkout's instructions. The [runbook](docs/AGENT_RUNBOOK.md) defines the required checkpoint and completion record.
