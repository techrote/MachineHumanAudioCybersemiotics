# Human gate: bibliographic database access for Track E

[Protocol §5](../PROTOCOL-v1.md#5-track-e-sources-and-searches) · [§13](../PROTOCOL-v1.md#13-access-gaps-and-human-gates) · Record: `HG-R002-DATABASE-ACCESS` · Status: **waiting** (not blocking protocol acceptance)

## Why this is needed

The agent can reach only a general web search engine. Its workspace proxy refuses the open bibliographic APIs (OpenAlex, Crossref, arXiv export, Semantic Scholar), and your Claude desktop app's built-in browser blocked `api.openalex.org` under its site permissions on 2026-10-13. In the pilot, web search returned only about 7% of a known set of eligible studies. Without a database channel, MHAC-R005 will run the declared fallback and must report that no bibliographic database was searched.

## What would close it (pick one)

**Option A — about a minute, preferred.** In the Claude desktop app's browser site permissions, allow `api.openalex.org` and `api.crossref.org` for the built-in browser (the block was set there, not by the sites). Then tell Claude in chat that OpenAlex is allowed. Claude does everything else, including paging and saving exports.

**Option B — only if A is impossible.** Open each link below in any browser and save the page as a `.json` file into one folder, then connect that folder to the chat ("+" → "Add folder" in the desktop app). These are first pages only (up to 200 results each); Claude will say if more pages are needed.

## Completion signal and stop condition

Complete when an OpenAlex URL opens for the agent, or export files are in a connected folder. If nothing changes before MHAC-R005 starts, R005 proceeds with the protocol §5.3 fallback and records the database channels as access gaps. Claude will not create accounts, buy access, bypass paywalls or contact anyone to get around this.
