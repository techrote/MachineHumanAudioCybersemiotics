# Provisional fictional message and truth contract

The **truth ledger** is independent of the dispatch policy. Each case has `messages` (ID, kind, source, integer `at`, and optional event `deadline`/`actor` or status `group`/`expires`), `changes` (source-authoritative `resolve`/`revoke`, nonresolving `ack`, or authority `handover`), `boundaries` (invented task opportunities), `initial_actor` and optional `clock_valid:false`. `truth.required` and `truth.released` are explicit independent labels for distinct event IDs; the loader rejects missing, contradictory or inconsistent labels. All statuses are replaceable *only within a declared source+semantic group*. Distinct obligations are never equivalent merely because they share a source.

- `queued` is a policy's tentative dispatch time; `dispatched` means modeled transmission. This abstraction does **not** model transport receipt, rendered audio, detected sound, understood message, action, or task completion. Those states remain unknown.
- `ack` is not `resolve`/`revoke`. No later status implies resolution. Explicit release before a planned dispatch makes dispatch *obsolete*, not an accomplished obligation. Released events are not counted as required at the checked horizon. Fixtures place release before their relevant deadlines; treatment of late revocation is not represented.
- A required event counts as **timely_authorized** only when emitted no later than its declared deadline, not released, with matching actor, known deadline and valid common clock. **No observation of human success** follows; this is a model gate. A required event lacking those conditions is **missed_required**; unknown is not silently promoted to pass.
- Both `deadline:null` and `actor:null` are **unknown**, not zero or permission. `clock_valid:false` blocks guaranteed deadline classification even if integer timestamps exist.
- `mean_status_sample_latency` is elapsed modeled time per delivered status, **not** a mathematical time-average Age of Information metric and not a measure of user awareness; statuses delivered after `expires` are explicitly stale.
- `duplicate_action_risk` counts repeated dispatch of one event ID; duplicate execution is *not* claimed. Delivery with a changed actor, after a deadline, after a release or with unknown preconditions has its own distinct counter.
- Policy (A) `immediate_fifo` emits each message at issue; (B) `fixed_deferral` delays every message three time units, including obligations; (C) `task_boundary` selects next declared boundary with a strict deadline-override (send immediately when boundary would be late); (D) `protected_coalesce` emits obligations immediately and replaces queued statuses in the same group; (E) `latest_wins_naive` replaces any still-pending message from the same source regardless of kind.

This toy contains no real queue contention, packet loss, uncertainty calibration, multi-hop delays, authenticated source validation, human workload inference, delivery receipts or action completion; `notifications` is modeled dispatch count rather than interruption burden. Heterogeneous clocks and actor handovers are adversarial *abstractions*, not a validated scheduling algorithm. Tie handling is deterministic: at the same logical tick, a newer arrival may replace a pending earlier dispatch.
