CSV includes start, count, onset count, phase level, elapsed and thread CPU microseconds, deadline and peak. Clocks and CSV output are offline only. No plugin callback instrumentation. Linux uses CLOCK_THREAD_CPUTIME_ID; Windows GetThreadTimes has potentially coarse accounting and individual block readings must not be treated as high-resolution CPU timing there; aggregate or use a separately qualified cycle counter. macOS not tested.

The 30 ms sleep positive control distinguishes elapsed and thread execution time but is not a calibration of DSP timer overhead. Timed region includes render plus timing overhead, while reference rendering, buffer allocation and CSV output are outside it. The reference render can perturb cache and scheduling; this is not a paced DAW test. Wall minus CPU is not a pure scheduler measurement. CPU time may include kernel execution and VM accounting artifacts; neither clock establishes causal attribution alone.
