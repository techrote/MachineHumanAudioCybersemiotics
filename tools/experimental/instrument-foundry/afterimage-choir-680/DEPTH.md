Prior native archive (010F) at 33ce22a3af27a9e1746f57a363376aadeaae3896 passed exact-head Windows 45845411264 and integrity 45845411305; its plugin still exposed only latest-only mode.

The adapter now exposes stable parameter 1605 Memory depth (three positions, normalized 0 / 0.5 / 1): latest-only / dual / archive. Existing IDs 1600–1604 and class IDs unchanged. Automation at a sample offset precedes note events; depth changes affect only subsequent note onsets. Missing history falls back to latest (initially zero); history is always retained at up to three qualifying completions even at depth 1. Changing depth does not clear history or retune already-sounding voices. Reset clears history, not depth. Cancellation remains transient. Bounded voice replacement remains unchanged.

Persistent eight-byte patch: AC01 magic for depth 1, exactly the legacy encoding; AC02 magic for depths 2 and 3 with (depth-1) stored in bits 28–29 of the little-endian 32-bit payload. Bits 30–31 reserved, depth encoding 3 invalid; AC01 must not contain nonzero depth bits, AC02 must not contain zero depth bits. New code reads legacy AC01; old code cannot read AC02. Back up projects before upgrading; preserve old binaries separately, do not install two copies with the same CID. History is not serialized. Existing packed 64-bit generation/patch handoff unchanged in width (30 payload bits now used); no audio-thread mutex.
