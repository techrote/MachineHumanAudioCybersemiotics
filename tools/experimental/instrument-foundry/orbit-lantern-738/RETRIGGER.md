# INST-011O — fallback-key retrigger recovery

Refs #738; Orbit Lantern is a creative interpretation of #265 at 56c107f8f4147316a588484c47be28bc8f840fbb. This change is engineering maintenance, not a new research result.

When a host emits noteId=-1, the bridge identifies notes by channel and pitch. Previously a released voice blocked the next note of the same pitch until its entire tail ended (up to one second). This made repeated articulations unusable with hosts that use fallback IDs. The new bridge permits one held voice per fallback key plus older release tails, up to the existing eight-voice capacity. Note-off and velocity-zero note-on prefer the currently held voice; if none is held, a repeated off remains idempotent while a tail exists. Native offSpectral follows the same selection. A duplicate held fallback key and a duplicate explicit ID are still refused; explicit IDs remain reserved until their tails end. There is no voice stealing. Late duplicate fallback note-offs cannot be distinguished from a legitimate off for a newly held note; this is an inherent ambiguity without explicit IDs. Channel isolation and the separate explicit-ID namespace remain intact.

The release flag is set only after a successful engine note-off and cleared on slot reuse/reset/prepare. Fixed-size voice scans remain bounded; no new audio-thread allocation or lock. The DSP oscillator, parameter IDs, factory IDs, state formats and build SDK pins are unchanged. The existing plugin adapter calls Live directly, so the repair applies when rebuilt. The Windows 0.3.0 binary previously delivered does not contain it.

Native regression: build with CMake and run ctest; orbit_host tests fallback versus unique explicit IDs with eight overlapping tails, four sample rates (8/44.1/48/96 kHz), all three release modes, velocity-zero offs, native spectral offs, repeated offs, capacity refusal, independent channels, slot reuse and reset. Exact stereo equality against the explicit-ID path and exact final silence are required. The new regression on the previous host.hpp failed at assertion 167. GCC 14.2 Release CTest 8/8; Clang 17 ASan/UBSan host probe PASS, both host probes 818460 checks. All 14 existing presets and 14 WAVs reproduce byte-for-byte against the qualified 0.3.0 archive. Same-agent engineering tests, not independent review, actual DAW compatibility, or hard real-time qualification. Exact-SDK Windows build and validator on this new source remain outstanding; local SDK clone DNS blocked. Do not substitute another SDK.
