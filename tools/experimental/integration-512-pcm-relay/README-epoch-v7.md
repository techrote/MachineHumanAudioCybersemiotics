## Acquisition API

EpochReceiver wraps the existing v4 Stream and preserves its grammar and binding checks. PCM16 16kHz, monotonic absolute sample timestamps including hypothesis starts, epoch IDs, pending/clear/overloaded acquisition state. Channel and context explicitly not inferred. An overflow emits its absolute timestamp and conservatively marks the whole current epoch as potentially containing unresolved evidence; this is not a retraction of already emitted valid receipts. Rearm discards unresolved state without finish/EOF and emits the exact discarded-sample interval [discardedFrom, at); previous evidence history belongs to caller. No acquisition event alone establishes context freshness or authority. Clear means no known cluster/pending candidate, not proof of silence or absence of unscanned evidence. No cross-epoch reconstruction.

Sticky: no rearm. Peak512: after overflow, require 8000 consecutive samples with abs <=512 (500 ms). Cooldown: consume/discard 320 samples (20 ms), then attempt reacquisition. Both capped at four resets per run by default. Once exhausted, remain overloaded. One live v4 ring of 153600 bytes plus fixed candidate state; new ring allocated per rearm, JS allocation/GC and caller-retained traces not bounded by ring alone. Not embedded realtime qualification. Single-sample adapter is intentionally conservative reference, not optimized.
