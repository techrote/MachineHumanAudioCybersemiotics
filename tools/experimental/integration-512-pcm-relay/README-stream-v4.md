## Contract and mechanism

Unchanged v2 wire, PCM16 mono 16 kHz. The v3 receiver rejected an entire window when two preambles were detected. V4 evaluates each detected cluster separately, using a 16-sample onset grid and thirteen clock scales .985 through 1.015, same purity/energy checks and complete GF(17), AST and public joint tag validation as v3. Each candidate waits 32,400 samples from its first detection for body evidence, or end-of-stream. A false preamble without a valid body does not veto another valid candidate. Valid intervals estimated across all valid clock hypotheses are conservatively compared; overlapping candidate interpretations cause abstention even if decoded packet values agree. This is not proof that physical origins are unique. No oracle slot boundaries, transmitted metadata, or message identity enters the streaming core. Onset-grid phase and threshold limitations remain; missing up to 320 terminal samples can satisfy the completeness predicate as in v3. A full frame is not authenticated by its public tag.

`Stream` owns a mirrored ring of 76,800 int16 entries (153,600 bytes, 38,400 distinct sample history). It retains at most eight closed pending clusters plus one forming cluster; each stores at most 13 hypotheses. Overspan or pending-cap overflow explicitly clears undecided work and halts further decisions for that stream instance; previously emitted evidence cannot be retroactively revoked. Output via synchronous callback; caller may accumulate arbitrary evidence, so `decode` convenience wrapper and test/browser are offline, not constant total memory. The CLI uses bounded chunks, outputs JSONL, validates canonical 44-byte WAV only. JS runtime heap/CPU and native streaming adapter not qualified; C++ v3 adapter remains unchanged. No guaranteed real-time operation.
