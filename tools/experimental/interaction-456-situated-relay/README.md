## Operate

Place core.js and index.html in the same folder and open index.html locally. Use Load interruption script then Advance scripted event, or manually publish a pump request, step once, publish a high-priority fan question, and advance until both complete. Select a receipt and actor; acknowledge, request repair, report a fictional action, or explicitly inject external fictional resolution. Revise the pump to a quotation addressed to the relay and attempt the old response. Switch policy and repeat. Export JSON and WAV for Observatory analysis. Playback is optional, stop is available; start at low device volume. No microphone, network, external libraries or real-device integration.

Native Node 18+: `node core.js output` generates qualification.json and interruption.wav. Browser and native Node CLI were not executed during authoring; the core was run twice in V8 and returned identical qualification receipts. ## Contracts

A world contains an integer tick (250 ms nominal), current record per source/event, bounded pending queue (16), one playing packet, completed receipt list, ordered log and audio segments. Inputs are publish(message), tick, respond(kind,actor,receipt), resolve(id,version,evidence). Exported API: world, msg, apply, replay, publish, tick, respond, resolve, render, wav, scenario, qualify. Replays use policy + input list; no wall clock or random seed. Publish increments per-event version and resets acknowledgement/action/resolution; cancels obsolete playback/queued packets. Higher priority preempts at the next tick boundary; interrupted packet restarts from its first segment. Expired packets are discarded. One repair per version when queue and deadline allow; no repair auto-loop. Acknowledgement needs a completed current receipt, correct actor and unexpired version under bound policy; action report additionally needs request scope and acknowledgement. Only explicit fictional evidence resolves. The latest-message comparator ignores actor, identity, validity and selected receipt for acknowledgements. Both use the same audio and channel schedule. It is deliberately weak, not a representative real-world protocol.

PCM16 mono 8 kHz, 250 ms per segment, two per packet, tapered sinusoid plus source-dependent harmonic, nominal amplitude <=0.1 full scale; source motif and scope/content motif, slightly lower amplitude for repair. This is an arbitrary original auditory convention, not a full acoustic serialization: identity, version, actor and receipt ID are symbolic side-channel metadata. No waveform decoder, actual listening or measured hearing, no physical safety or secure authentication. Model uses one channel, two agents/events, exact ticks, perfect receipt metadata, finite scripted inputs. Logs and segments grow with interaction duration; queue is bounded but sustained priority traffic can starve lower priority packets. Browser buttons do not model continuous real-time arrival; playback of each step can be stopped/replaced by the user. No claim of accessibility or screen-independent operation. Digital peak is not calibrated SPL.

## Results

64 enumerated conditions (six Boolean switches: competing message, revision, handover, wrong actor, expiry, missing receipt), each tested with two policies; switches have redundant combinations, not independent empirical samples. 4 valid original acknowledgements, 60 invalid. Bound: 4 accepted, 0 wrong target/invalid accepts, 0 missed valid. Latest: 64 accepted, 62 wrong target/invalid accepts, 2 missed valid targets (wrong-target accept is also a miss). Separate deterministic interruption/restart, repair, explicit action and resolution, stale revision, scope and PCM checks. 479 assertions per run, two identical runs; measured peak 2918/32768, no human hearing data. First negative witness mask 1: pump receipt r1, fan receipt r2 arrives, operator's acknowledgement of r1 is applied to fan by latest policy. qualification.json contains full witness and selected interaction trace/segments. Results are consequences of the constructed policy and fixtures; no estimates of human performance.
