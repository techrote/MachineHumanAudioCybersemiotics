# FX-011I — pending-window capture and discard

Refs #748, #264 and draft #265 at 56c107f8f4147316a588484c47be28bc8f840fbb. Creative DSP extension, not a general escape solver or human evidence. Predecessor d8b22eaa976c38f71ce858b8a3478bc695d046d5. Native only; no new VST3 parameters or bank state format.

`Processor::discardPendingInput()` clears both channel sums and signed peaks, preserving elapsed window count, clock phase, interpolation endpoints, lattice, reference history and pending truncation pulse. It is equivalent to zeroing the elapsed input prefix, not resetting the clock or averaging denominator. `HarmonicBank::discardPendingInput(band)` exposes an explicit per-band discard. `MemoryBand::discardOnClose` optionally applies the same operation on the rising-to-falling excitation gate edge, alongside the existing filter reset. Default false retains FX-011H behavior. Gate closure means hold (stop new drive), not immediate commit; erase remains a separate operation. Already committed state is not undone. Calls are audio-thread-owned and bounded; no allocation, lock or I/O. Monitor conservatively: memory may persist until erased with zero input.
