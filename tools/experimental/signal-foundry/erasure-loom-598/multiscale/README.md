# Erasure Loom — fixed-latency multiscale laboratory (FX-007E)

Refs #598, #321. Pinned research `332e1029b30f20cf3f9eab52ac0b21c65c8688e8`, section "Exact two-erasure law and restoring one probe". The existing reconstruction rows are a direct implementation of the pinned periodic degree-three model. Variable temporal spacing and continuously warmed paths are creative engineering extensions, not general restoration or perceptual evidence. This is a native laboratory, not the 0.2.0 VST3 adapter.

Three nine-node paths have chunk widths 16, 128 and 1024 samples. At 48 kHz the frame spans 3, 24 and 192 ms. Every path uses the same sanitized inputs, frame-latched geometry/repair/probe/edge, and existing bounded coefficients. A 9216-sample circular buffer per path captures frames and writes reconstructed samples into the future playback positions. Both erased values for a lane are calculated before either is overwritten. All paths are continuously warm; a common dry ring and the wet paths have identical 9216-sample latency. Selection 0/1/2 retargets a convex 20 ms crossfade from its current weights. Wet, gain and bypass slew over 5 ms at the aligned output. Fixed latency is 192 ms at 48 kHz; conservative tail 18432 samples. No allocation, I/O or locks in step(); construct the engine off the audio thread (approximately 0.6 MB storage). Sample-rate changes require prepare/reset. Geometry updates latch independently on each path's capture-frame boundary; switching timescale does not reset capture or transport. Coarse frame computation is a bounded but concentrated burst, so worst-case callback deadline and aliasing remain unqualified. No zero-latency or transparent arbitrary-audio claim.

The 16-sample path matches the 0.2.0 DSP after additional alignment for the static controls tested. This lab's fixed latency is intentionally **not** substituted for the existing plugin's 144 samples. A future adapter should either be a distinct effect/class or explicitly negotiate latency without silently changing existing sessions. No existing class IDs, EL02 state or SDK lock changed. The inherited exact official SDK is tag `v3.8.0_build_66`, root `9fad9770f2ae8542ab1a548a68c1ad1ac690abe0` and seven pins in ../SDK-GITLINKS.txt. SDK is not needed for native builds.

## Build and audition

From this directory: `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release`, `cmake --build build --config Release`, `ctest --test-dir build -C Release --output-on-failure`. Or build the parent native project, which now registers this test. Run scales_demo from a writable directory (Windows multi-config: build/Release/scales_demo.exe). Five original 6-second stereo PCM16 WAVs plus tail: aligned reference, fine, medium, coarse and a scale switch every half second. Separation=1, rotation=0, budget=2, repair=1, probe=.25, edge=.5, wet/gain=1; reference bypassed. For a dropout patch, repair=0 and probe=0; for a gentler texture try wet=.5 and edge=.8. Start with low monitoring gain. No external material or service.
