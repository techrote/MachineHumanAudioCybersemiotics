# FX-004C — spectral-routing compiler

Refs #536, #528/#529, #416/#417 (0039dbdead33f28b7eefb4ad5680aa05d437ff29, finite projector alphabet). Creative design/measurement extension, not a new mathematical proof or human evidence. Parent cfcf31c4a230016088314baacc2e665da74704b5 is the qualified Windows plugin source. No plugin or state changes.

Offline C++17 exhaustive design tool: choose four distinct delay values (1–1024), a total delay budget, sample rate and 1–64 frequency/right-power targets. Search all 16^4 ordered stage assignments, rejecting programs over budget; minimize unweighted mean squared right-power error. Exact floating-score ties prefer shorter total delay, then enumeration order. Not global optimization outside this finite alphabet, nor exact algebraic proof. No target interpolation or guaranteed between-probe behavior. DC/Nyquist cannot achieve half power in this family. Search never runs in audio callback.

Build from this directory: `cmake -S . -B build; cmake --build build --config Release; ctest --test-dir build -C Release --output-on-failure`. Run compiler_cli (Release subdirectory on multi-config builds) with arguments `48000 120 8 16 32 64 375 0 750 1 1125 0 1500 1 1875 0 2250 1`. Enter printed L/R/S/D and delays in the existing plugin, forward, wet 100%, bypass off. Use a second identical instance with inverse enabled to reconstruct both channels with total delay; keep input below 1/16 FS, no clipping or changing settings. Sample rate changes require redesign. The CLI uses decimal Hz and fractional right power, not dB. Baseline uses S32/L32/R32/L24 (single mixing stage, 120-sample tail).

Run compiler_demo in writable directory to generate four stereo PCM16 little-endian files at 48 kHz, patch.txt and routing.csv. Wrap PCM using Python wave (2 channels, 2 bytes, 48000 Hz); original successive faded tones only. Demo observed D8/L64/D16/S8, 96-sample tail, 37888 feasible assignments, MSE 0.083333333333333273 vs baseline 0.29166666666666669; 750 and 2250 Hz miss targets by 0.5.
