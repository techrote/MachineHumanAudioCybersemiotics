# FX-009N — sample-clock geometry scheduling

Refs #674/#675; #338/#339 at f8b9bddd89c2d174b28f060bf34b42d2ca9a0e64, sections 2–4. Engineering extension of the creative finite-receipt DSP interpretation; not scientific validation or evidence of human effects.

`multi::Scheduled` is an audio-thread-owned wrapper around the optimized `multi::Live`. Submit complete, valid configurations with `request()` before the corresponding sample. Invalid requests do not mutate pending or active state. At sample zero and every `max(32, ceil(sample_rate * 0.001))` samples thereafter, the latest request is applied atomically as a configuration. Intermediate expensive-control requests are intentionally coalesced, not queued. Resolution, matching count, geometry seed, receipt budget, contract, receipt seed and epoch duration are deferred together; wet/bypass targets take effect on the submitted sample and retain existing 5 ms ramps. The period is independent of block partition. At 48 kHz it is 48 frames; maximum ordinary waiting time is 47 frames. At 1 kHz it is 32 frames (31 ms worst wait). No audio latency is introduced; this is control latency.

The existing receipt clock can still cause an internal transfer rebuild, possibly on the same sample as a scheduled configuration commit. The wrapper bounds external expensive commits to one per period; it does not guarantee a CPU deadline. `reset()` and `prepare()` are lifecycle-only, promote the latest request, and restart both clocks. Save `requested()` using MR01 for a persistent patch, not a snapshot of the internal clock. `active()` reports the admitted configuration. This wrapper is not thread-safe and must not be used as a host-to-audio mailbox. There are no new allocations, locks or logging on the audio path. Existing single-pair plugin and MR01 representation are unchanged.

Build the existing native CMake project and execute `receipt_fold_multi_scheduled_test` (also registered with CTest). Its reference applies complete configurations on absolute sample-clock boundaries and only cheap targets between them. Tests cover five sample rates, three block partitions, float32/64, dense mixed requests, malformed requests, resets, exact silence, nonfinite input, MR01 restoration and invalid sample-rate rejection. The offline elapsed-time stress test submits 48,000 geometry requests in 1,500 32-frame blocks at 48 kHz and verifies exactly 1,000 admissions. Timing is environment-dependent and does not establish DAW callback qualification. Prior unrestricted-automation failures remain relevant and are not erased by changing the control contract.

No new VST3 parameters, state format, adapter, SDK dependency or plugin binary in this revision.
