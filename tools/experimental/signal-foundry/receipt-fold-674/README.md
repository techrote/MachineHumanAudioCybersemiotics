# Receipt Fold — FX-009A

Refs #674, #338/#339, pinned f8b9bddd89c2d174b28f060bf34b42d2ca9a0e64, sections 2–3. Direct finite pair-collapse realization plus creative quantized audio sonification. Source draft is not accepted research. No participant or physical recovery claims.

Eight quantized states; one action collapses a chosen higher state into a lower one. Four contracts: no tag (choose lower on ambiguity), fixed low-bit tag, trusted preview selects a differing binary digit, full three-bit tag. The decoder knows the action. Preview mask is metadata supplied by the scheduler before encoding; three possible hints require two fixed preview bits. Full and preview recover quantized indices only, not original continuous audio. All 28 pair actions, eight states: 28/12/0/0 wrong and 56/24/0/0 ambiguous out of 224 per mode. Equal weighting is a synthetic enumeration, not a population estimate. The audio engine runs encoding and decoding locally; no external side channel or late-action recovery claim. Invalid/missing receipts are not equivalent to verified reconstruction.

Native C++17 per-frame engine with independently usable encode/collapse/decode. Stereo independent, zero algorithmic latency, zero tail, wet default zero, 5 ms wet slew; zero input forced to zero. Wet output bounded by 0.4375 FS, mixed output bounded by 1 FS. Quantization and discrete action changes can click/alias; this is an intentionally coarse effect and not a smooth reconstruction filter. No allocation, lock or I/O in frame(). Caller must serialize controls and rendering. Pair/index helpers assume valid states and a pair produced by pair(). No host adapter/state/class IDs yet.

Build: cmake -S . -B build -DCMAKE_BUILD_TYPE=Release; cmake --build build --config Release; ctest --test-dir build -C Release --output-on-failure. Run receipt_fold_lab --render in a writable directory for four original three-second stereo 48 kHz PCM16 demos. Preview and full are intentionally identical; absent and fixed differ in final demo. Initial demo selected only same-parity pairs and fixed/absent were identical; changed the schedule to cover both cases. Try wet 0.35 and pairs (1,6) or (2,6); first distinguishes fixed low-bit tags, second does not.
