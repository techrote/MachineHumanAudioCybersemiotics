## Controls and sound

All controls are normalized 0–1. Parameter IDs 600–605 in order: signed drive (gamma=2*drive-1), coupling, cross-only isolation, mix, wet gain, bypass. Defaults 0.75, 1, 0, 0.5, 0.75, 0. Drive 0.5 is neutral, above it expands and adds cubic partials, below it compresses/folds depending on energy. Coupling zero is independent-channel cubic processing, one is shared stereo energy. Isolation one removes dry and self-cubic terms from the wet branch, leaving only gamma*coupling*L*R^2 and gamma*coupling*R*L^2. The cross-only output vanishes when either channel is silent. Wet gain is linear and applies only to wet. The bypass returns protected dry. Use conservative monitoring levels; this is a deliberately nonlinear research effect, not a transparent limiter.

Suggested settings (drive/coupling/isolation/mix/gain/bypass):
- Shared Warmth: 0.3/1/0/0.7/0.8/0.
- Cross Witness: 1/1/1/1/1/0 (quiet at low input; don't compensate with unsafe monitor gain).
- Independent Contrast: 0.95/0/0/1/0.65/0.
- Formal I/Q: 1/1/0/1/1/0, with coherent real/imaginary input channels and enough headroom to avoid clamping.

For the formal setting, z=L+iR and y=z+z|z|^2. In the supplied coherent low-frequency example with three active carriers of amplitude 0.18 at 480,720,800 Hz, the 400 Hz carrier is absent at input but generated by 480+720-800 (two ordered terms, amplitude 0.011664). Move 800 to 880 Hz to use a Sidon grid; the 400 Hz product disappears in the ideal cubic model. Ordinary stereo is not generally an analytic signal; this theorem does not apply to arbitrary audio or channel downmixes. No anti-alias filtering or oversampling in this version: actual sampled aliasing can create new products, demonstrated by the regression folding 26 kHz to -22 kHz at 48 kHz. Clipping also breaks the exact cubic contract. The research's stationary coherent phase cycling and fifth-order model are not implemented here.

## Native build and reproduction

CMake 3.25+, C++17: `cmake -S . -B build; cmake --build build --config Release; ctest --test-dir build -C Release --output-on-failure`. Run forge_demo (Release subdirectory on multi-config builds) in a writable folder. It writes seven original stereo signed little-endian PCM16 files, 48 kHz. `python render.py` in that folder converts these to WAV and reports peak, RMS and coherent 400 Hz I/Q projection for the four grid files. Stereo demos use original overlapping decaying tones; dry, shared-energy and cross-only wet signals use the same source. They are not loudness matched. No subjective audition. The core supports Float32 and Float64, and tests exercise rates 8–384 kHz, five block partitions, automation target boundaries, zero tail and channel symmetry/independence. Parameter targets slew at finite full-scale 5 ms, not a DAW interpolation guarantee. No allocation, locks, I/O or history in core process; guard nonfinite/tiny values and clamp inputs and outputs to +/-1 FS. Protected bypass is not bit-transparent for out-of-range/nonfinite input. State WF01 is 28 bytes: four magic bytes then six normalized IEEE binary32 little-endian values. Transactional decode; future migration not yet applicable. State stores targets, not instantaneous slew values. Stereo only, declared latency and tail both zero.
